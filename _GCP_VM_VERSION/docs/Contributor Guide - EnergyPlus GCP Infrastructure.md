# Infrastructure and Collaboration Guide: EnergyPlus Simulations on Google Cloud

This document serves as a complementary guide for researchers and technical collaborators involved in the development and execution of large-scale thermo-energy simulations using EnergyPlus and Google Cloud Platform (GCP) infrastructure. The main focus is on standardizing the development environment and optimizing computational resources.

## 1. Development Environment Setup

To ensure parity between local and production (cloud) development environments, all collaborators must configure VS Code with the following extensions and tools:

* **Google Cloud Code:** Essential for visual management of Buckets, secrets, and instance monitoring.
* **Google Compute Engine MCP Extension:** Enables infrastructure management via natural language commands and automation.
* **Google Cloud CLI (gcloud):** Required for authentication and high-performance terminal operations.

### Initial Authentication

Before starting any task, run the command below in the terminal to configure Application Default Credentials (ADC):

```bash
gcloud auth application-default login
```

## 2. Instance Management (Compute Engine)

Unlike limited interactive environments, definitive simulations should run on dedicated instances. The table below summarizes hardware recommendations for different project scales:

| Task Type | Recommended Machine Series | Main Advantage |
| :---- | :---- | :---- |
| Prototyping / Debug | E2 (e.g., e2-medium) | Cost-effective for initial testing. |
| Parametric Simulation | N2 or N4 (High-CPU) | Balance between performance and CPU throughput. |
| Multi-objective Optimization | C3 or C3D | High memory bandwidth for compute-intensive calculations. |

## 3. Data Pipeline with Google Cloud Storage (GCS)

Manipulation of IDF and EPW files, as well as collection of CSV/SQL results, must exclusively use the `gcloud storage` command to maximize transfer speed.

### Essential Workflow Commands

* **Input sync:** `gcloud storage rsync ./models gs://[BUCKET]/models`
* **Results retrieval:** `gcloud storage cp gs://[BUCKET]/output/*.csv ./results`
* **Temp cleanup:** `gcloud storage rm gs://[BUCKET]/temp/**`

**Technical Note:** The JSON-based task engine of `gcloud storage` is significantly faster than the legacy `gsutil`, especially for large volumes of small files generated by EnergyPlus.

## 4. Security and Secrets Management

Storing API keys or service account credentials in source code (GitHub) is strictly prohibited. All collaborators must:

1. Use **Secret Manager** to store connection strings or tokens.
2. Access secrets programmatically via the GCP Python client library.
3. Use bound identities (Workload Identity) when running scripts inside VMs.

## 5. Advanced Python API Integration (pyenergyplus)

For optimizations requiring real-time interaction with the physics engine (such as the CP-SAT solver), collaborators should avoid reading/writing files to disk on each iteration. Using pyenergyplus enables:

* Simulation state management directly in RAM.
* Simulation interruption via *callbacks* for dynamic parameter adjustment (actuators and sensors).
* Parallel execution without data contamination between simulation instances.
